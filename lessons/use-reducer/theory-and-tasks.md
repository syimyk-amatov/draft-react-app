# React Практика: useReducer Hook

## 1. Теория

### Проблема (Complex State Logic)
Иногда состояние компонента становится слишком сложным для `useState`. Например, когда:
- Состояние состоит из множества полей.
- Следующее состояние зависит от предыдущего сложным образом.
- Одно действие пользователя обновляет несколько частей состояния одновременно (например, "начать загрузку" -> `isLoading: true`, `error: null`).

`useState` может привести к раздутым обработчикам событий и рассинхрону.

### Решение (useReducer)
`useReducer` — это альтернатива `useState` для более сложной логики. Он работает по принципу Redux:
1.  **State**: Текущее состояние.
2.  **Dispatcher**: Функция для отправки "сигналов" (actions) об изменении.
3.  **Reducer**: Чистая функция `(state, action) => newState`, которая решает, *как именно* изменить состояние в ответ на action.

```tsx
const [state, dispatch] = useReducer(reducer, initialState);

// dispatch({ type: 'INCREMENT' })
```

## 2. Задача 1: Расширенный счетчик (Basic Syntax)

Познакомьтесь с синтаксисом и потоком данных.

### Сценарий
Нужно создать счетчик, который не просто увеличивается, но имеет ограничения (мин/макс) и шаг изменения. Вся логика проверок должна быть изолирована.

### Требования:
1.  Создайте компонент `CounterReducer`.
2.  **State**: `{ count: 0, step: 1, max: 10, min: 0 }`.
3.  **Reducer**: Реализуйте функцию `counterReducer`, обрабатывающую экшены:
    *   `INCREMENT`: увеличивает `count` на `step`. Нельзя превышать `max`.
    *   `DECREMENT`: уменьшает `count` на `step`. Нельзя опускаться ниже `min`.
    *   `SET_STEP`: меняет шаг.
    *   `RESET`: сбрасывает `count` в 0.
4.  **UI**:
    *   Отображение текущего счетчика.
    *   Кнопки `+` и `-`.
    *   Инпут или кнопки для выбора шага (1, 5, 10).
    *   Кнопка Reset.
5.  **Логика**: Попробуйте нажать `+` много раз. Счетчик должен остановиться на 10. Логика "остановки" должна быть *внутри редюсера*, а не в обработчике `onClick`.

## 3. Задача 2: Управление формой и валидацией (Complex Object)

`useReducer` отлично подходит для форм, где валидация одного поля может зависеть от других, или где состояние формы включает метаданные (touched, errors, isSubmitting).

### Сценарий
Форма логина с валидацией "на лету".

### Требования:
1.  Создайте компонент `LoginForm`.
2.  **Initial State**:
    ```javascript
    {
      email: '',
      password: '',
      errors: { email: null, password: null },
      isSubmitting: false,
      isSuccess: false
    }
    ```
3.  **Actions**:
    *   `CHANGE_BIT`: `{ type: 'CHANGE_FIELD', field: 'email', value: '...' }` — обновляет поле и *сбрасывает ошибку* этого поля.
    *   `VALIDATE`: Проверяет поля.
        *   Если email без '@' -> ошибка.
        *   Если пароль < 6 символов -> ошибка.
    *   `SUBMIT_START`: ставит `isSubmitting: true`.
    *   `SUBMIT_SUCCESS`: ставит `isSuccess: true`, `isSubmitting: false`.
4.  **Reducer**:
    *   Вся логика обновления `errors` при вводе или сабмите должна быть здесь.
5.  **UI**:
    *   Два инпута.
    *   Кнопка "Войти" (disabled, если `isSubmitting`).
    *   Сообщения об ошибках под инпутами (красным).
    *   Сообщение "Успешно!" если `isSuccess`.
6.  **Flow**:
    *   Пользователь вводит данные -> dispatch `CHANGE_FIELD`.
    *   Нажимает Submit -> dispatch `VALIDATE`.
    *   Если в new state есть ошибки -> стоп.
    *   Если нет -> dispatch `SUBMIT_START`, `setTimeout` 2 сек, dispatch `SUBMIT_SUCCESS`.

## 4. Задача 3: Shopping Cart (Array Mutations)

Работа с массивами в редюсере: добавление, удаление, обновление количества.

### Сценарий
Корзина товаров интернет-магазина.

### Требования:
1.  Создайте компонент `ShoppingCart`.
2.  **Товары**: Массив доступных продуктов (hardcoded): `[{id: 1, name: 'Apple', price: 100}, {id: 2, name: 'Banana', price: 50}]`.
3.  **State корзины**: `items: []` (где элементы: `{ productId: 1, quantity: 2 }`).
4.  **Reducer Actions**:
    *   `ADD_ITEM`:
        *   Если товара нет в корзине -> добавить с quantity: 1.
        *   Если есть -> увеличить quantity на 1.
    *   `REMOVE_ITEM`: полностью удалить товар из корзины.
    *   `DECREMENT_ITEM`:
        *   Уменьшить quantity на 1.
        *   Если quantity становится 0 -> удалить товар.
    *   `CLEAR_CART`.
5.  **UI**:
    *   Список "Продукты": кнопки "Купить".
    *   Список "Корзина": Название, Кол-во (+/-), Удалить, Цена за строку (price * qty).
    *   Итоговая сумма всей корзины (можно посчитать `useMemo` или прямо в рендере).
