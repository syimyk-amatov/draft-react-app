# Хук `useEffectEvent`

## Теория

В React эффекты (`useEffect`) должны объявлять все реактивные значения (состояние, пропсы), которые они используют внутри, в массиве зависимостей. Из-за этого изменение *любого* из этих значений приводит к перезапуску (очистке и новому вызову) эффекта.

Однако часто бывает нужно прочитать внутри эффекта **самое свежее состояние или пропсы**, не вызывая при этом его перезапуск. Для решения этой проблемы предназначен экспериментальный хук `useEffectEvent` (ранее предлагался как `useEvent`).

Синтаксис:
```tsx
import { experimental_useEffectEvent as useEffectEvent } from 'react';

const onConnected = useEffectEvent((roomId) => {
  // Эта функция имеет доступ к самым последним пропсам и стейту (напр. theme, userName),
  // но сама функция не изменяется при их изменении, и её не нужно указывать в зависимостях эффекта,
  // что защищает эффект от перезапуска.
  showNotification(`Joined ${roomId} as ${userName} with theme ${theme}`);
});

useEffect(() => {
  const connection = createConnection(roomId);
  connection.on('connected', () => {
    onConnected(roomId); // Вызов Effect Event
  });
  connection.connect();
  
  return () => connection.disconnect();
}, [roomId]); // Только roomId является зависимостью!
```

*Примечание:* Effect Events (события эффекта) можно вызывать **только изнутри эффектов**. Их нельзя передавать в DOM-узлы (например, в `onClick`).

## Задачи

### Задача 1: Аналитика подключения к чату (`AnalyticsChat`)

**Проблема:** Ваш компонент чата подключается к серверу при монтировании (и при смене комнаты). Когда подключение установлено, необходимо отправить событие в систему аналитики, передав `roomId` и текущую тему интерфейса (`theme`). Если тема меняется, мы **не должны** переподключаться к чату. Но в обычный `useEffect` придется добавить `theme` в зависимости, из-за чего смена темы (Светлая/Темная) заставит пользователя переподключаться к комнате, теряя историю сообщений.

**Требования:**
- Используйте `useEffectEvent`, чтобы создать "нереактивную" функцию `onVisitAnalytics`.
- Эта функция должна выводить логи в консоль и показывать уведомление (с помощью `alert` или `console.log`) о том, что произошел вход, и использовать актуальную `theme` из состояния без перезапуска сокетов.

### Задача 2: Автосохранение черновика без сброса таймера (`AutoSaveDraft`)

**Проблема:** У вас есть поле ввода для написания длинной статьи. Вы хотите настроить автосохранение введенного текста каждые 5 секунд с помощью `setInterval` внутри `useEffect`. Если вы передадите текст в эффект, вам нужно будет добавить его в зависимости `[text]`. Но тогда *каждый раз, когда пользователь вводит символ*, таймер будет сбрасываться! Это значит, что если пользователь печатает не прекращая, автосохранение не сработает ни разу, пока он не сделает паузу в 5 секунд.

**Требования:**
- Отделите логику интервала от логики чтения состояния.
- Настройте таймер только на монтирование и очистку на размонтирование (зависимости `[]` или `[intervalMs]`).
- Используйте `useEffectEvent` для упаковки функции `saveDraft()`, которая берет актуальный `text` из стейта и сохраняет его.
