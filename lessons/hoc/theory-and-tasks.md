# Компоненты высшего порядка (HOC - Higher-Order Components)

## Теория

HOC (Higher-Order Component) — это продвинутая техника в React для повторного использования логики компонентов. По сути, HOC — это функция, которая принимает компонент и возвращает новый компонент. 

```tsx
const EnhancedComponent = withHigherOrderLogic(WrappedComponent);
```

HOC часто используются для:
- Управления доступом (Access Control / Authorization)
- Логирования (Logging / Analytics)
- Инъекции данных (Data Fetching / State Management)
- Обработки ошибок и состояний загрузки

Правила работы с HOC:
1. Не мутируйте оригинальный компонент. Возвращайте новый.
2. Прокидывайте (forward) неоригинальные пропсы `WrappedComponent`.
3. Максимально сохраняйте `displayName` для удобной отладки в React DevTools.
4. (Продвинуто) Копируйте статические методы, если это необходимо.

### Задача 1: Контроль доступа (`withAccessControl`)

Вам необходимо реализовать HOC `withAccessControl`, который скрывает компонент от пользователей, не имеющих необходимых прав доступа.

**Требования:**
- HOC должен принимать массив разрешенных ролей (напр., `['admin', 'editor']`).
- HOC должен принимать опциональный компонент-заглушку `FallbackComponent`, который будет отображаться, если доступа нет.
- Для получения текущей роли пользователя используйте предоставленный мок-хук `useAuth()`.
- Вы не должны потерять типизацию пропсов `WrappedComponent`.
- Установите правильный `displayName` возвращаемому компоненту (например, `WithAccessControl(AdminDashboard)`).

### Задача 2: Автоматическое количество попыток загрузки (`withAutoRetry`)

Вам необходимо создать HOC для обертывания компонентов, которые требуют данных, загружаемых по сети. HOC должен взять на себя ответственность за вызов функции-загрузчика, управление состоянием `loading` / `error`, а также механизм повторных попыток (retries), если сеть недоступна или сервер возвращает ошибку.

**Требования:**
- HOC загружает данные асинхронно через переданную в него функцию `fetchFn`.
- Пока данные грузятся, возвращаемый компонент показывает спиннер/скелетон.
- Если произошла ошибка HOC должен попытаться вызвать функцию снова до `maxRetries` раз с задержкой между попытками (напр., 500ms).
- Если после `maxRetries` данные не загружены, отобразить сообщение об ошибке.
- Если данные успешно загружены, HOC должен отрендерить `WrappedComponent` и передать ему полученные данные как проп `data`, а также прокинуть остальные внешние пропсы компонента.
- Типизация: HOC обязан быть дженериком, чтобы тип данных `T`, возвращаемый из `fetchFn`, корректно матчился с типом пропа `data` у обернутого компонента.

- `src/lessons/HOC/AutoRetryLoader/AutoRetryLoaderDemo.tsx`
