# React Практика: useTransition Hook

## 1. Теория

### Проблема (Blocking Updates)
В React по умолчанию все обновления состояния считаются срочными (urgent). Если вы обновляете состояние (например, фильтруете большой список) в ответ на ввод в input, интерфейс может "фризить" или лагать, потому что React пытается перерисовать тяжелый список одновременно с обновлением текста в инпуте.

### Решение (Concurrency)
`useTransition` позволяет пометить некоторые обновления состояния как **несрочные** (non-urgent). React выполнит их в фоновом режиме, не блокируя пользовательский интерфейс (например, ввод текста останется отзывчивым).

```tsx
const [isPending, startTransition] = useTransition();

// ...
onChange={(e) => {
  setInputValue(e.target.value); // Срочное обновление (инпут)

  startTransition(() => {
    setFilter(e.target.value);   // Несрочное тяжелое обновление (список)
  });
}}
```

*   **isPending**: `true`, пока несрочное обновление выполняется (полезно для показа спиннера).
*   **startTransition**: Функция, оборачивающая обновление состояния, которое можно отложить.

## 2. Задача 1: Лагающий фильтр (Slow List)

Научитесь разделять быстрые и медленные обновления.

### Сценарий
У нас есть большой список элементов (например, 10 000 строк). При вводе текста в поиск интерфейс тормозит, так как фильтрация и рендеринг занимают много времени. Нужно сделать ввод плавным.

### Требования:
1.  Создайте компонент `SlowList`.
2.  **Данные**: Сгенерируйте массив из 5000-10000 строк (например, "Item 1", "Item 2"...).
3.  **State**:
    *   `inputValue`: для значения инпута.
    *   `query`: для фильтрации списка.
4.  **UI**:
    *   Input для поиска.
    *   Список отфильтрованных элементов.
5.  **Реализация без `useTransition` (для сравнения)**:
    *   Сначала сделайте так, чтобы `setQuery(value)` вызывался прямо в `onChange`. Заметьте лаги при быстром вводе.
6.  **Реализация c `useTransition`**:
    *   Оберните `setQuery` в `startTransition`.
    *   `setInputValue` оставьте снаружи (он должен быть быстрым).
    *   Используйте `isPending`, чтобы показать текст "Loading list..." рядом со списком, пока он фильтруется.
    *   Заметьте, что инпут теперь не тормозит, даже если список обновляется с задержкой.

## 3. Задача 2: Переключение табов (Tab Navigation)

Использование переходов для навигации по "тяжелым" страницам без блокировки UI.

### Сценарий
Приложение с тремя вкладками: "Home", "Posts" (тяжелая), "Contact". При клике на "Posts" интерфейс зависает, и пользователь не понимает, нажалась ли кнопка.

### Требования:
1.  Создайте компонент `TabContainer`.
2.  **Компоненты табов**:
    *   `Home`: Простой текст.
    *   `Contact`: Простой текст.
    *   `Posts`: Компонент, который искусственно замедляет рендер (например, внутри него цикл `while` на 50-100мс или создание 2000 дочерних элементов `PostItem`).
3.  **State**: `activeTab` (строка).
4.  **UI**:
    *   Кнопки навигации (Home | Posts | Contact).
    *   Контент активного таба.
5.  **Логика**:
    *   Оберните переключение таба `setActiveTab` в `startTransition`.
    *   Пока идет переход (`isPending`), подсвечивайте нажатую кнопку или показывайте глобальный индикатор загрузки (например, полоску сверху), но **старый таб** должен оставаться видимым до окончания загрузки нового.
    *   Это создает ощущение "быстрого" интерфейса, даже если следующий экран еще готовится.
